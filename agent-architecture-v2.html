BIS 观点提取 · 多 Agent 架构 v2

代码调度 + 并行独立视角 + 对抗审查 + 确定性校验 —— 机制参照 OpenAI 万 agent 数学集群案例

管线分层（数据流向，自上而下）

  • • 层0 代码调度器：替代 LLM 逐批 task 派发，gather + Semaphore 并发 4~6
  • • 数据面：章节切片策略链 + 图片提取 + context pack（一次构建全场共享）
  • • 层1 worker 池：区间 × 3 视角扇出（buried-lede / 逆共识 / 数据拐点）+ chart-reader 按图派发
  • • 层2 对抗审查：独立 agent 逐条攻击候选，不知道产出者是谁
  • • 层3 确定性校验：quote 必须是原文子串（归一化后），代码层强制
  • • 层4 submit_insight 逐条写回 ON，事件经 SSE 实时透传前端

OpenAI 万 agent 案例 → 本架构映射

  • • 编排是代码不是 LLM（Codex 调度）→ 层0 调度器
  • • 并行独立路线、互不知"最优答案" → 三视角 worker 互不可见
  • • 提议与审查分离（对抗性 agent）→ adversarial-review
  • • Lean 形式化验证不信任自评 → quote 逐字子串校验
  • • 中间结果蒸馏前传（Euler→Navier-Stokes）→ context pack 注入全部 worker
  • • 峰值 10000 并发对我们无意义：瓶颈是 GLM TPM，不是调度

动态扩展点（代码级开闭扩展）

  • • 切片策略注册表：新建模块文件即注册，outline → 字号/正则 → 字符兜底自动降级
  • • SubAgent 注册表：沿用现有 pkgutil 自动发现，新增视角/审查者零改动接入
  • • dispatch 声明：range（区间）/ document（全文一次）/ per-image（按图），调度器按声明决定派发形状
  • • SubAgentContext 加字段即全员可见（frozen dataclass + 默认值，旧代理零改动）
  • • 注意：WSL inotify 失效，新增能力需重启 agent 生效（运行时热插拔是伪需求）
